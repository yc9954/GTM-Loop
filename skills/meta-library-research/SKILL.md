# 준의 광고 레퍼런스 조사

먼저 브랜드·대상·국가·언어·여행/식사 맥락·목표 행동·공개 가능한 제품 근거를 확인한다. Soban Tales는 작은 인물의 조리 이야기가 실제 식사로 연결되는 개발 중인 경험이다. 일반 음식 영상의 조회수만으로 적합성을 판단하지 않는다.

## 관찰

[Meta 광고 라이브러리](https://www.facebook.com/ads/library/)에서 검색어/광고주/국가/상태/플랫폼 필터와 확인 시각을 남긴다. 도구가 제공되면 읽기 기능을 쓰고, 없으면 브라우저를 사용한다. 접근 실패 시 실제 오류와 남은 조사를 적는다. 임의 광고 ID, 캡처, 감상, 성과를 만들지 않는다. 기존 meta-ads CLI는 자사 광고 계정 기능이며 공개 라이브러리 검색기가 아니다.

처음에는 소수의 서로 다른 표현 원리를 비교한다. 같은 광고주·같은 크리에이티브의 변형은 묶어서 중복 집계를 피한다. 영상은 실제 본 구간과 타임코드를 기록한다. 썸네일만 확인했다면 훅·동작·편집 분석은 미확인이다.

| 보존 항목 | 관찰 내용 |
|---|---|
| 식별 | 원본 링크, Library ID, 광고주, 확인일, 검색 조건, 실제 노출된 상태/기간 |
| 표현 | 처음 시선을 잡는 요소, 주인공/소재, 배경, 사건→변화, 구도, 컷 리듬, 사운드, 문구, CTA |
| 적합성 | 우리 고객의 질문, 제품과의 공통점/차이, 재사용할 표현 원리, 제외할 요소 |
| 근거 한계 | 실제 본 구간, 미확인 요소, 성과 자료 제공 여부 |

‘오래 게재’, 변형 수, 화면의 화려함은 참고 신호다. 실제 CTR·전환율·ROAS가 제공되지 않으면 **성과 미확인 레퍼런스**로 표시한다. 좋은 표현과 검증된 성과를 별도 열로 둔다. 공개 정보 범위는 국가와 광고 유형에 따라 달라지므로 보이지 않는 필드를 추정하지 않는다.

## 표현을 우리 제품에 맞추기

후보마다 `고객 질문 → 표현 원리 → Soban에서 보여줄 사건 → 필요한 실제 제품 장면 → 보조 스톡 → 확인할 반응`을 한 줄로 연결한다. 잘 맞는 하나와 다른 접근의 대안 하나를 골라 이유를 쓴다. 적합하지 않은 후보도 제외 이유를 남긴다.

소재·배경·행동·관찰점은 바꿀 수 있는 입력이다. 예를 들어 큰 도구를 두 작은 인물이 함께 움직이는 장면은 크기 대비와 협동을 전달할 수 있다. 이것이 사용자의 아이디어라면 실제 제품에서 그 행동이 보이는지 검토하고, 없으면 필요한 제작 샷으로 남긴다. 레퍼런스의 브랜드·캐릭터·컷 순서·음악을 그대로 가져오지 않는다.

광고 라이브러리는 소재 이용 허가를 주는 창구가 아니다. 댄에게는 복사할 경쟁 광고 파일 대신 **필요한 행동·앵글·동작·길이·질감**과 링크를 넘긴다. 자신의 승인된 제작본/허용된 스톡/허용된 생성 입력으로 구현한다. 알렉스에게 훅의 목적·사건 흐름·편집 변화·제품 이해의 검증 질문을 넘긴다.

미아님·낸ㅣ님 검토 초안에는 추천 이유, 제품과 다른 지점, 카피가 약속하는 경험, 아직 필요한 장면을 보이게 한다. 검토 요청을 준비했다는 사실을 검토·승인 완료로 기록하지 않는다.
