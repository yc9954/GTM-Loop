# Project Table 협업 기준

## 책임과 인계

| 사람 | 사용자 지정 역할 | 다음 사람에게 남길 것 |
|---|---|---|
| 준 | GA 분석, Meta 광고 라이브러리의 좋은 표현 수집 | 기간·분모·근거·가설, 레퍼런스 링크와 차용 원리 |
| 댄 | 무료 이용 가능한 소재 수집, Pexels/Higgsfield 재가공 | 실제 사용할 파일·원본 링크·이용 조건·검토된 구간·미확보 샷 |
| 알렉스 | 영상 구도와 편집 | 샷별 사건·구도·타임라인·사운드·출력본·변경 내역 |
| 미아님·낸ㅣ님 | 사용자 지정 상시 협업자. 세부 담당·최종 승인권 미확정 | 같은 버전의 대상·메시지·제품 근거·콘티·CTA에 대한 검토 기록 |

두 협업자를 이름만 CC에 두지 않는다. 기획 선택 전, 공개 후보 검토, 결과 해석에 의견을 연결한다. 실제로 누구의 응답을 기다릴지는 그 사이클의 `reviewers_required`에 사용자와 합의한 범위로 기록한다. 초깃값은 두 사람을 포함한 **제안**이다. 응답 부재를 동의로 처리하지 않는다. 준의 분석 소유권이 예산·게시·브랜드 최종 승인권까지 자동으로 정하지는 않는다.

## 시점별 무엇이 달라지는가

아래 주기는 시작 제안이다. 계정 반영 지연·집행 규모·출시 일정·팀 합의에 맞춰 조절한다. 예약 작업을 설치한 상태가 아니다.

| 계기 | 읽을 근거 | 판단·인계 |
|---|---|---|
| 집행/게시 중 매일 | GA 수집 이상, 키워드 광고 비용·검색어, 새 문의·반론 | 장애·명백한 부적합 검색어·오해를 알리고 다음 조사를 지정. 당일 성과로 승자 선언 금지 |
| 게시 후 초기 검토 | 실제 데이터 반영을 확인한 24–48시간 이후 자료 | 링크·계측·서비스 이해를 우선 확인. 지연되면 검토일 변경 |
| 주간, 또는 실험 표본 충족 | 같은 요일·기간의 성과와 고객 반응, 유사 콘텐츠 | 다음 한 가지 가설, 유지할 부분, 댄·알렉스 작업 브리프 |
| 새 제작본/메뉴/일정 확정 직후 | 제작본 버전·검토 범위·공개 상태 | 사용할 샷과 카피를 갱신. 예전 승인 전체 재사용 금지 |
| 공개 직전 | 최종 편집본, 사용 자산 권리, CTA 목적지, 사람 의견 | 기술·미술·제품·권리·요청된 검토를 따로 확인 |
| 행사/파일럿 직후 | 현장 관찰·직원 의견·관객 이해·불편 | 온라인 흥미와 실제 서비스 품질을 대조하고 제작/운영 개선 분리 |

신선도는 `checked_at`만으로 정하지 않는다. 새로 연 보고서도 `data_through`가 오래됐을 수 있다. GA와 광고 성과의 유효 기간은 사이클에 입력하며 Google 처리 시간의 보증으로 취급하지 않는다. 출시 전 광고를 안 하면 검색 광고는 사유를 적고 `not_applicable`. 접근 실패는 `missing`이다. 0건이라는 관찰에는 정상 수집·완료된 기간·분모가 필요하다.

## 콘텐츠와 제품이 맞물리는 검토

콘텐츠별로 **대상 질문 → 약속 → 화면에서 입증할 사건 → 실제 자산 → 목표 행동 → 관측 근거**를 연결한다.

- 관객이 “음식 영상 계정인가?”라고 이해했다는 근거가 있으면, 서울 풍경을 더 넣기 전에 **식탁에서 작은 인물의 요리와 실제 식사를 경험한다**는 장면이 있는지 확인한다.
- 클릭이 약하면 훅을, 클릭 뒤 문의가 약하면 제품 이해·제안·도착 페이지를 조사한다. 상관만으로 원인을 확정하지 않는다.
- 소재·배경·사건의 긴 이야기가 좋아도 실제 제품 장면이 없으면 제품 증명의 공백이 남는다. 스톡 인물의 웃음이나 생성된 후기를 실제 고객 반응으로 쓰지 않는다.
- 자체 제작 중인 영상은 공개 허용 상태를 확인한다. 일부 시연 가능한 컷의 승인을 전체 공연 승인으로 넓히지 않는다. Soban의 고정 투사본과 이동 카메라 광고는 구분한다.

검토자가 말한 조건을 다음 버전의 체크 항목으로 이월한다. 의견 불일치는 두 안·차이·근거·결정 담당자를 적고, 편집자가 조용히 다수결을 만들지 않는다.

## 소스와 제작 경로

`asset_id / source_type / version / in-out / intended_claim / usage / rights_source / checked_at / reviewer / review_scope`를 유지한다. source_type은 own_production, licensed_stock, generated, reference_only 중 실제 출처에 맞게 쓴다. reference_only는 편집 소스에 넣지 않는다.

[Pexels 공식 라이선스](https://www.pexels.com/license/)는 무료 사용·수정을 허용하되 보증/추천 암시 등 제한이 있다. 무료 이용 허가와 저작권 없음은 다르다. 음악·인물·상표·재업로드/AI 입력 조건은 실제 자료별 확인 사항이며 가공으로 소멸하지 않는다.

[Higgsfield Genjutsu](https://higgsfield.ai/genjutsu)가 공식 표기다(사용자 초기 표기 Jenjutsu). 공식 소개는 동작 전이·요소 교체를 제공한다. 사이트 기능 소개, 현재 계정 도구 지원, 선택한 입력의 실제 생성 성공은 다른 증거다. 생성 직전에 가용 기능·입력·가격을 확인한다. 무료 스톡이라고 생성 비용도 무료인 것은 아니다.

댄의 `codex/dan`에서 main에 통합된 두 스킬에는 filmed-stock 전용 작업의 제약이 있다. 이를 전체 프로젝트의 생성 금지로 확대하거나 이번 준 브랜치에서 그 작업을 덮어쓰지 않는다. 이번 요청처럼 자체 영상+스톡+허용된 생성물 혼합이 필요하면 별도 샷 계획에서 출처별로 명시하고 해당 작업 범위로 실행한다.

## 실행 기록 규칙

사이클 원자료·계정 ID·고객 인용 원문·연락처·미공개 자산은 로컬 작업 기록에 둔다. 공개 저장소에는 스킬·빈 양식·비식별 예시만 저장한다. 도구 연결은 실제 읽기 성공 후 연결됨으로 표시한다. 데이터 리소스나 IAM을 바꾸는 작업은 조직의 접근 거버넌스를 먼저 따른다.
