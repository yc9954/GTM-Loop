# 준의 성과 분석

Soban Tales는 개발 중인 테이블 프로젝션 다이닝이다. 실제 프로젝트의 최신 제품 맥락을 먼저 읽는다. 예약·판매가 열렸다고 가정하지 않는다. 목표는 조회수 보고가 아니라 다음 콘텐츠에서 바꿀 요소 하나를 근거와 함께 고르는 것이다.

## 읽을 수 있는 근거부터

연결된 GA 도구를 먼저 확인하고, 없으면 제공된 GA 내보내기 파일을 읽는다. 계정·속성·기간·속성 시간대·필터·조회 시각·데이터가 반영된 시점·계측 이벤트를 기록한다. 연결이 없으면 `미연결`이다. 0명·0전환으로 채우지 않는다. 계정 식별자와 원자료는 공개 저장소에 올리지 않는다.

저장소에서 실행한다면 기존 `tools/clis/ga4.js`의 읽기 보고서 기능을 사용할 수 있다. 페이지네이션으로 누락 행을 확인한다. 토큰은 로컬 환경에서만 읽고 출력하지 않는다. 이벤트 전송·설정 변경은 분석에 필요하지 않다. 단독 스킬 설치에서는 CLI가 함께 설치되지 않으므로 가용 도구 또는 CSV를 사용한다.

GA는 소셜 플랫폼의 영상 완주율이나 프레임별 반응을 대신하지 않는다. 해당 지표는 실제 광고·소셜 계정 자료에서 읽고 `creative_id`로 연결한다. UTM은 `utm_content=creative_id.variant_id` 같은 일관된 규칙을 쓰되 기존 규칙을 먼저 보존한다. 링크가 없거나 ID가 유실되면 연결 불가로 남긴다.

## 비교와 판단

1. 같은 길이·요일·국가·채널·목표 이벤트의 기간을 비교한다. 당일 미완성 데이터는 이상 징후 탐지에만 사용한다. GA 처리에는 24–48시간이 걸릴 수 있고 값이 바뀔 수 있다. 계정별 실제 반영 상태를 확인한다. [Google 공식 데이터 신선도](https://support.google.com/analytics/answer/11198161?hl=en).
2. 유입량, 참여 세션, 목표 행동의 분자·분모, 비용이 있는 경우 비용과 전환을 함께 본다. 목표 이벤트를 여러 번 한 사람과 전환 건수를 혼동하지 않는다. 분모 0은 비율 계산 불가이며 결측은 0이 아니다. 데이터 제한·샘플링·(other)·동의 설정 영향과 관측기간을 기록한다.
3. 관심 등록/문의/예약/방문은 다른 단계다. 제품이 아직 팔리지 않으면 검증된 문의·대기 등록 등의 목표를 사용한다. 현장 이해도·서빙 안정성은 GA로 판단하지 않는다.
4. 키워드 광고는 광고 플랫폼의 **검색어와 입찰 키워드**를 구분한다. 검색어·매치 유형·노출·클릭·비용·목표 행동·통화·기여 기간을 비교한다. 브랜드/비브랜드, 방문 의도/정보 탐색을 분리한다. 공개 검색 결과로 CPC·집행 성과를 추정하지 않는다. Search Console은 자연 검색 자료다.
5. 같은 콘텐츠라도 노출·배치·국가·예산이 다르면 훅의 효과로 단정하지 않는다. 낮은 표본에서는 승자를 정하지 말고 관찰 기간 또는 이해도 인터뷰를 제안한다. 실제 실험은 ab-testing의 사전 기준으로 판단한다.
6. 댓글·문의·인터뷰의 반론을 customer-research 방식으로 대조한다. “좋다”와 서비스 이해·방문의향·구매 행동을 구분한다. 출처·시각·표본 모집 방식 없는 반응은 검증 근거로 승격하지 않는다.

## 인계 결과

`creative_id / 관찰 / 근거·기간 / 불확실성 / 가설 / 한 가지 변경 / 유지 요소 / 성공 기준·중단 조건 / 다음 검토일 / 담당자`를 남긴다. 미아님·낸ㅣ님에게는 수치표 전체 대신 판단에 필요한 관찰과 질문, 비교할 두 안을 전달할 **검토 초안**을 만든다. 발송은 별도 요청 범위에 따른다.

예: 클릭은 많은데 문의가 적고 인터뷰에서 “음식 영상 채널”로 오해했다면, 다음 가설은 실제 테이블에서 식사하는 경험을 첫 장면에서 읽히게 하는 것이다. 오해 근거가 없으면 이 결론을 만들어내지 않는다. 댄에게 필요한 소스, 알렉스에게 바꿀 샷과 보존할 컷을 같은 콘텐츠 ID로 넘긴다.

보고는 결과 → 근거 → 불확실성 → 다음 행동 순서. 증거가 없으면 계측 준비안과 자료 누락을 제출한다. 분석을 끝냈다고 계정 연결·광고 집행이 완료됐다고 쓰지 않는다.
